Building a native Markdown renderer in Zig with an architecture utilizing `mmap.zig`, `simd.zig`, and `macos.m` gives you the perfect foundation for mechanical sympathy. To hit that absolute limit of hardware efficiency while maintaining a 120fps+ fluid interface, the architecture needs to decouple block discovery from fine-grained text shaping.

**Zero-Copy, SoA Abstract Syntax Tree (AST)**
Your parser (`parser.zig`) should never allocate memory for strings. Every text node must simply be a `u32` start index and a `u16` length pointing back into the `mmap` buffer.

* **Struct of Arrays (SoA):** Zig’s `MultiArrayList` is critical here. Instead of a node graph scattered across the heap causing cache misses, pack the AST into flat arrays.
* **Index-Based Graph:** Use `u32` indices for `parent`, `first_child`, and `next_sibling` relationships instead of 64-bit pointers. This halves your RAM footprint and ensures your CPU prefetcher stays saturated while traversing the tree.

**Two-Pass Lazy Parsing via SIMD**
Parsing a 50,000-word document synchronously will stutter the UI. Use the `simd.zig` module to split parsing into two phases:

1. **Coarse Block Discovery (Sync):** Use SIMD bitmasks to blaze through the `mmap` buffer, looking only for `\n`, `#`, `>`, and ``` to identify high-level block boundaries (paragraphs, headings, code blocks). Do not parse inline formatting (bold, italics, links) yet.
2. **Viewport-Triggered Refinement (Lazy):** Only parse inline Markdown syntax for the specific blocks intersecting the active viewport boundaries tracked by `viewport.zig`.



**Virtualized Layout & Scroll Anchoring**
A flawlessly smooth scroll requires avoiding full-document layout calculations.

* **Estimated Heights:** When the document loads, assign an estimated height to every off-screen block based on its byte length and the current window width.
* **Just-in-Time Layout:** As the user scrolls, `viewport.zig` triggers exact layout calculations only for blocks entering the screen.
* **Silent Offset Correction:** If a block's actual rendered height differs from its estimated height, apply the delta to the total scroll height *and* the current scroll position simultaneously. This prevents the scrollbar from jumping and masks the lazy computation from the user.

**Aggressive Shaping and Glyph Caching**
Text shaping (e.g., via CoreText in `macos.m`) is the most CPU-intensive part of rendering.

* **Word-Level Hashing:** Cache shaped glyph runs at the word level, keyed by a hash of the text slice and its active style (e.g., `SpaceGrotesk-Bold`). Markdown features a lot of repeating plain text; reusing shaped runs across paragraphs drastically cuts CPU time.


* **Texture Atlasing:** Rasterize glyphs into a single packed GPU texture atlas. The renderer should just be dumping textured quads (two triangles per character) to the GPU, avoiding CPU-side compositing entirely.

**Event-Driven Idling**
To save battery, the application must drop to 0% CPU usage when idle. Ensure the macOS run loop in `macos.m` is completely event-driven. Do not use a continuous `while (true)` game loop. Hook into `CADisplayLink` strictly for driving active animations (like the `sample_animated.gif`) or kinetic scrolling momentum, and disable the link the millisecond the screen becomes static. Only redraw the specific dirty rectangles that change.
